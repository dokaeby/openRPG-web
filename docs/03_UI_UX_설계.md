# 03. UI/UX 설계

## 1. 비주얼 디렉션

이 게임의 UI는 화면이 아니라 "탐험가의 장비"처럼 보이게 한다. 플레이어가 지도와 필사본을 펼쳐놓고 여행을 기록하는 느낌을 목표로 한다.

핵심 선택은 세 가지다.

**재질감**: 양피지와 잉크, 그리고 놋쇠 장식. 패널은 종이 질감을, 테두리는 얇은 금속선을 쓴다. 유리나 플라스틱 느낌의 현대적 UI는 쓰지 않는다.

**색**: 따뜻한 베이지 바탕 위에 진한 녹색과 적갈색으로 정보 계층을 나눈다. 보라색/파란색 마법 계열은 마법 UI에만 쓴다.

**타이포그래피**: 제목은 세리프 서체로 "책의 제목"처럼, 본문은 가독성이 좋은 고딕 계열로 둔다. 게임 안 대사와 퀘스트 텍스트가 "읽을거리"처럼 느껴지게 하는 것이 목적이다.

## 1.1 렌더링과 UI 계층

- **월드 렌더링**: Three.js 기반 로우폴리 3D + 툰 셰이딩. 모델은 glTF/GLB, Draco 압축 사용.
- **UI 계층**: 캔버스 위에 DOM/CSS로 구현한다. 게임 UI를 이미지가 아니라 실제 DOM으로 만들면 텍스트 품질, 접근성, 반응형이 웹 플랫폼의 강점을 그대로 쓴다.
- **UI와 월드의 분리**: DOM UI는 Three.js 씬과 독립적이다. UI가 렌더링 성능에 영향을 주지 않도록, HUD는 CSS transform/opacity만으로 애니메이션한다.
- **해상도 대응**: UI는 `rem`/`em` 기준으로 작성하고, 1080p에서 1rem=16px 기준으로 스케일한다. 최소 지원 너비 1280px.

## 2. 디자인 토큰

컴포넌트는 토큰만 참조한다. 하드코딩된 색상이나 크기는 쓰지 않는다. (astryx 원칙: 토큰/컴포넌트 우선)

### 색상 팔레트

| 토큰 | 값 | 용도 |
|------|-----|------|
| `parchment` | `#F2E8D5` | 기본 배경 (양피지) |
| `parchment-dark` | `#E4D6BC` | 보조 배경, 입력 필드 |
| `ink` | `#2B2620` | 본문 텍스트, 선 |
| `ink-soft` | `#5C5347` | 보조 텍스트 |
| `forest` | `#2F4A3C` | 주요 액션, HP, 성공 상태 |
| `oxblood` | `#7A2E2E` | 경고, 위험, 적대 표시 |
| `brass` | `#B08D3E` | 테두리 장식, 보상 표시 |
| `night` | `#1B1B22` | 어두운 HUD 패널 배경 (밤/던전) |
| `arcane` | `#4A3A6B` | 마법 관련 UI 전용 |

상태색 규칙: 성공=forest, 경고=oxblood, 정보=brass, 마법=arcane. 같은 색을 두 용도로 쓰지 않는다.

### 타이포그래피

| 역할 | 서체 | 크기 기준 (1080p) | 용도 |
|------|------|-------------------|------|
| Display | 나눔명조 (또는 Marcellus) | 32~40px | 화면 제목, 퀘스트 이름 |
| Title | 나눔명조 | 20~24px | 패널 제목, 섹션 헤더 |
| Body | Pretendard/Noto Sans KR | 16~18px | 본문, 설명, 수치 |
| Caption | Pretendard/Noto Sans KR | 13~14px | 라벨, 단축키 힌트 |

영문이 섞이는 경우 Display는 Cinzel 계열을 쓴다.

### 간격/레이아웃

- 기본 그리드 단위: 8px. 모든 여백/패딩은 8의 배수.
- 패널 모서리: 큰 패널 12px, 버튼 6px. 둥근 정도를 계층별로 구분한다.
- HUD는 화면 가장자리 24px 안쪽에 배치한다.

## 3. 화면 구성

### 3.1 게임 플레이 중 HUD

```
┌──────────────────────────────────────────────────────┐
│ [미니맵]            [버프/상태이상]      [시간·날씨]  │
│                                                      │
│                                                      │
│                 (게임 월드)                          │
│                                                      │
│                                                      │
│ [시스템 로그]        [퀘스트 트래커]    [HP/MP/스태미나]│
│                                                      │
│ [스킬 바] [아이템 바] [상호작용 키]                  │
└──────────────────────────────────────────────────────┘
```

HUD 원칙:
- 게임 화면을 가리지 않는다. 패널은 기본 반투명, 마우스를 올리면 불투명해진다.
- 중요한 정보(HP, 목표)만 항상 보인다. 나머지는 접을 수 있다.
- 상호작용 가능한 대상이 가까우면 화면 하단에 `[F] 대화하기` 같은 키 힌트를 띄운다.

### 3.2 컴포넌트 인벤토리

| 컴포넌트 | 설명 | 비고 |
|----------|------|------|
| `HudPanel` | 반투명 기본 패널 | 모든 HUD의 베이스 |
| `ResourceBar` | HP/MP/스태미나 바 | 손실 시 깜빡임, 위험 시 펄스 |
| `SkillSlot` | 스킬 단축키 슬롯 | 쿨타임은 원형 스윕 오버레이 |
| `ItemSlot` | 인벤토리/장비 슬롯 | 등급별 테두리 색상 |
| `QuestTracker` | 우측 진행 퀘스트 목록 | 클릭 시 퀘스트 상세 |
| `Minimap` | 미니맵 | 미발견 지역은 안개 처리 |
| `DialogueBox` | 대화창 | 선택지는 버튼 목록 |
| `Toast` | 획득/완료 알림 | 상단 중앙, 3초 후 자동 소멸 |
| `Tooltip` | 아이템/스킬 상세 | 호버 시 지연 표시 |
| `Modal` | 확인/설정 팝업 | 배경 딤 처리 |

### 3.3 메뉴 구조

메뉴는 `Esc` 또는 메뉴 버튼으로 연다. 탭 구성:

- **캐릭터**: 스탯, 장비, 스킬 트리
- **가방**: 인벤토리, 장비 비교
- **퀘스트**: 진행/완료 목록
- **지도**: 전체 맵, 발견 지역, 빠른 이동
- **제작**: 레시피, 재료 현황
- **설정**: 그래픽, 사운드, 조작, 게임플레이
- **저장/불러오기**

각 탭은 같은 프레임을 공유하고 내용만 바꾼다. 메뉴를 열어도 게임은 일시정지된다(싱글플레이 기준).

## 4. 전투 UI

- 적 머리 위에 이름과 HP 바. 보스는 화면 상단에 큰 HP 바 + 페이즈 표시.
- 데미지 숫자는 머리 위에 떠오르는 텍스트로 표시한다. 크리티컬은 크기와 색을 다르게.
- 상태이상은 캐릭터 발밑 또는 머리 위에 작은 아이콘으로.
- 타겟팅: Tab 또는 마우스로 대상 선택. 선택된 대상은 테두리 강조.
- 전투 로그는 기본 접힘, 전투 중에는 최근 5줄만 표시한다.

## 5. 텍스트와 카피

UI 문구는 게임 세계의 목소리를 따른다. 시스템 용어를 그대로 쓰지 않는다.

- 버튼은 행동을 그대로 쓴다: "저장하기", "제작하기". "확인"만 있는 버튼은 피한다.
- 퀘스트는 "무엇을, 어디서, 왜"를 한 줄에 담는다. "~을 도와주세요" 같은 모호한 문구 대신 구체적인 목표를 쓴다.
- 오류 메시지는 원인과 해결책을 함께 쓴다. "아이템을 사용할 수 없습니다"가 아니라 "마나가 부족합니다"처럼.
- 빈 화면은 다음 행동을 제안한다. 빈 퀘스트 목록에는 "마을 게시판에서 퀘스트를 확인하세요"처럼 안내를 둔다.
- 대사체와 UI체를 구분한다. UI는 짧고 명령형, NPC 대사는 캐릭터 말투를 따른다.

## 6. 모션

- 화면 전환(메뉴 열기/닫기)은 0.2~0.3초 페이드+살짝의 이동.
- 데미지 숫자, 아이템 획득 팝업은 위로 떠오르며 페이드 아웃.
- 반복되는 장식 애니메이션은 쓰지 않는다. 미니맵의 깜빡임 정도만 허용한다.
- 설정에 "모션 줄이기" 옵션을 둔다.

## 7. 접근성

- UI 크기 3단계(작게/보통/크게), 최소 본문 14px.
- 색만으로 상태를 구분하지 않는다. HP 바에는 항상 숫자 병기.
- 키보드만으로 모든 메뉴 조작 가능.
- 자막/텍스트 크기 옵션, 음성·효과음 볼륨 분리.

## 8. 화면 플로우

### 게임 시작
```
타이틀 → 새 게임/불러오기 → 종족 선택 → 클래스 선택 → 이름/외형 → 오프닝 → 튜토리얼 → 자유 탐험
```

- 종족 선택 화면은 종족별 실루엣 일러스트와 한 줄 소개, 고유 스킬 미리보기를 보여준다.
- 캐릭터 생성은 최소화한다. 외형 커스터마이징은 출시에 선택 기능으로 미룬다.

### 전투 플로우
```
필드 이동 → 적 발견/접촉 → 전투 진입(필드 전환 없이) → 전투 종료 → 보상 팝업 → 필드 복귀
```

### 상호작용
```
NPC 접근 → [F] 키 힌트 표시 → 대화창 → 선택지/퀘스트 수락 → 결과 반영
```

## 9. 에셋 가이드

- **3D 모델**: glTF/GLB, 삼각형 수 상한을 프롭/캐릭터/배경으로 나눠 관리한다. Draco 압축 필수.
- **텍스처**: 1024px 기준, 팔레트 텍스처 + 라이트맵 베이크로 톤을 유지한다.
- **UI 프레임**: DOM/CSS로 구현하므로 이미지 스프라이트 대신 CSS border/background로 처리한다. 장식 요소만 SVG/PNG로 둔다.
- **아이콘**: 64×64 기준, 등급별 테두리 색상을 §2 팔레트에서 가져온다.
- **폰트**: 웹폰트로 서빙한다. 나눔명조/Pretendard 등 SIL OFL 계열은 상업적 사용 가능. 폰트 서브셋으로 초기 로딩을 줄인다.
- **오디오**: Web Audio API로 재생, 포맷은 OGG(MP3 폴백). 존별 BGM은 페이드 전환.
