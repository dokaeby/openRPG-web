## 1. 의도와 배경

이 프로젝트는 자유롭게 탐험하는 오픈월드 판타지 RPG를 만드는 것이다. 여러 종족이 공존하는 세계를 배경으로, 플레이어가 종족과 클래스를 선택해 성장하고 모험하는 게임을 목표로 한다.

기존 상용 RPG가 이미 잘 만든 영역(대화 시스템, 제작, 퀘스트 분기)을 다시 만들기보다, 종족 간 관계와 탐험의 자유도에 차별점을 둔다. 성공했을 때의 모습은 "플레이어가 자기만의 종족 조합과 탐험 경로를 만들어가는 경험"이다.

## 2. 목표 / 비목표 / 안티목표

### 목표
- 종족 선택이 실제 플레이에 영향을 주는 게임 (스탯만이 아니라 대화, 상점, 접근 가능 지역까지)
- 연결된 대륙을 걸어서 탐험할 수 있는 오픈월드
- 메인 퀘스트 완주가 가능한 수직 슬라이스
- 데이터 주도 설계로 콘텐츠 추가가 쉬운 구조

### 비목표
- 싱글플레이어 우선. 멀티플레이는 출시 후 과제로 미룬다.
- AAA급 그래픽. 아트 파이프라인이 감당할 수 있는 범위의 비주얼을 목표로 한다.
- 실제 서비스/수익화 설계. 이 문서는 프로토타입 단계까지의 설계다.

### 안티목표 (이것이 실패면 기술적으로 성공해도 실패)
- 모든 종족이 사실상 같은 게임이 되는 것 (스킨 차이만 있는 상태)
- 맵이 넓기만 하고 갈 곳이 없는 것
- 퀘스트가 전부 "몬스터 N마리 잡기"인 것

## 3. 핵심 플레이 경험

1. **탐험**: 종족마다 접근하기 쉬운 지역과 어려운 지역이 다르다. 엘프는 숲에서, 드워프는 지하에서 유리하다.
2. **성장**: 레벨, 스킬, 장비를 통해 점점 더 위험한 지역에 도전한다.
3. **전투**: 세미리얼 ATB 방식 (근거는 §5 접근법 비교).
4. **제작/경제**: 채집과 제작으로 장비를 만들고, 지역별 상점에서 거래한다.
5. **서사**: 메인 퀘스트와 종족별 스토리가 서로 연결된다.

## 4. 타겟 플랫폼과 규모 가정

- **1차 플랫폼**: 웹 브라우저 (설치 없이 실행, 정적 호스팅 배포)
- **렌더링**: 단순화된 3D (로우폴리 + 툰 셰이딩)
- **기술 스택**: TypeScript + Three.js + DOM UI (근거는 05번 문서)
- **추후 전환**: Unity 마이그레이션 예정. `core`/`data` 계층을 엔진 비의존으로 유지해 이식 비용을 줄인다.
- **기준 해상도**: 1920×1080, 반응형 UI 지원
- 예상 개발 규모: 소규모~중소규모 팀 기준 12~24개월 프로토타입

## 5. 주요 설계 결정과 접근법 비교

설계 문서에는 검토한 대안과 선택 근거를 남긴다.

### 전투 방식

| 접근법 | 장점 | 단점 | 판단 |
|--------|------|------|------|
| 실시간 액션 | 몰입감, 조작 재미 | 구현 복잡, 밸런싱 어려움, 인디 리소스에 부담 | 보류 |
| 전통적 턴제 | 구현 단순, 밸런싱 용이 | 액션성 부족 | 차선책 |
| 세미리얼 ATB | 액션성과 구현 난이도의 균형, 데이터 주도 가능 | 입력 반응 속도 튜닝 필요 | **채택** |

### 콘텐츠 규모 전략

| 접근법 | 장점 | 단점 | 판단 |
|--------|------|------|------|
| 수작업 맵 대량 제작 | 품질 안정 | 시간과 인력 소모, 스코프 크리프 위험 | 기각 |
| 절차적 생성 | 빠른 맵 확장 | 품질 편차, 손으로 다듬기 어려움 | 부분 채택 (필드 소품만) |
| 존 단위 수작업 + 데이터 주도 몬스터/퀘스트 | 품질과 생산성의 균형 | 파이프라인 설계 필요 | **채택** |

### 저장/데이터

| 접근법 | 장점 | 단점 | 판단 |
|--------|------|------|------|
| Unity 내장 직렬화 | 구현 빠름 | 버전 호환성 취약 | 기각 |
| JSON/YAML 데이터 파일 + TS 타입 + zod 스키마 | 버전 관리, 검증 가능, Unity 이식 용이 | 초기 파이프라인 설계 필요 | **채택** |

## 6. 제약 조건

- 팀 규모와 기간이 제한적이므로 콘텐츠 양보다 시스템 완성도를 우선한다.
- 오픈월드 성능(로딩, 드로우콜)은 별도 프로파일링이 필요하다.
- 모든 데이터는 스키마 검증을 거쳐야 한다. 잘못된 데이터가 런타임에 터지면 안 된다.

## 8. 성공 기준

프로토타입 단계의 완료 조건으로 본다.

- 플레이어가 종족 6종과 클래스 4종을 선택해 시작할 수 있다
- 최소 3개 존을 걸어서 이동할 수 있다
- 메인 퀘스트 10개와 종족 퀘스트가 동작한다
- 세이브/로드가 안정적이다

서비스 단계의 지표(세션 시간, 완주율 등)는 프로토타입 이후에 정한다.
